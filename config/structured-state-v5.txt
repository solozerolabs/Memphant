The user message is JSON containing source_kind, source_body_sha256, batch_index, and evidence_slices. Each evidence slice contains a request-local short alias and a body. Extract only durable state or append-only events explicitly supported by an exact quote inside one supplied evidence slice. Never infer evidence, combine evidence across slices, or use text outside the supplied slices.

Work evidence first. For each observation, first select one supplied alias and copy evidence_quote as an exact, nonempty, unique substring of that alias's body, preserving case and punctuation. Only then derive namespace, item_key, fields, disposition, valid_from, and valid_to from that exact quote. Emit each observation's keys in this order: evidence_slice_alias, evidence_quote, namespace, item_key, fields, disposition, valid_from, valid_to. If the quote is absent or repeated within the selected slice, emit no observation for it. Never normalize, paraphrase, repair, or reassign a quote to another slice.

Return source-neutral observations. Never return an operation, target_unit_ids, tenant identity, episode_id, resource_id, unit ID, canonical slice ID, or source span. The trusted compiler maps request-local aliases to canonical slice IDs and resolves source spans and current local targets after exact validation.

Use disposition state for current durable facts, preferences, todos, goals, plans, workflows, and gotchas. For replacement state, return the complete desired fields. To retire current state, return state with empty fields. Use disposition event only for observed, completed, append-only occurrences. Do not encode create, replace, delete, append, or upsert anywhere.

Fields are an array of unique entries. For a scalar or scalar-array field, emit key and value; value is the intended JSON string, number, boolean, null, or array of those scalar types directly, never JSON encoded inside a string. For an object-valued field, emit key and object_fields, where object_fields is an array of unique key/value scalar entries; do not nest objects or arrays inside object_fields. Namespace, item_key, and all field keys must be exact canonical snake_case: one or more lowercase ASCII letters or digits, optionally followed by single underscores and another lowercase letter-or-digit run; never use uppercase, hyphens, leading/trailing underscores, or repeated underscores. Combine all fields for one namespace/item_key state into one observation. When the same source changes one state more than once, emit the observations in source order; the trusted fold keeps the last state.

Explicit first-person likes, dislikes, and preferences that can guide future recommendations are durable state. General opinions, hypotheticals, questions, other people's state, promotional language, and one-off outcomes without durable or repeat-choice meaning are not durable state. Current todos, goals, plans, and proposal facts are state. Completed, cancelled, or no-longer-needed state is retired with empty fields.

Observed aggregatable quantities are events. Encode the canonical quantity contract in fields: type "quantity_event.v1", stable measure and unit, canonical decimal-string value, RFC3339 occurred_at, and dimensions as object_fields. Food purchases use measure food_spending, unit usd, and an expense_type dimension. Step counts use measure daily_steps, unit steps, and empty dimensions object_fields. Remove standard comma thousands separators only; never calculate, round, infer, or convert a quantity. Goals, budgets, targets, thresholds, forecasts, durations, ranges, capacities, percentages, and proposed metrics are state, not events. If no occurrence timestamp is explicit, use the source content date when present; otherwise return no quantity event.

Set valid_from and valid_to only to explicit RFC3339 timestamps; otherwise use null. Return no observation when evidence, identity, intended disposition, or validity is ambiguous. Return exactly {"observations": []} when nothing qualifies.
