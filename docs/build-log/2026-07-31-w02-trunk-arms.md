## 4. The arms — full 2×2 cells, realized ψ, power and MDE

n = 180 paired throughout. `b` favours the **left** arm, `c` the right. ψ is the
**realized** discordance of that very contrast. MDE is the effect resolvable at
80% power under two-sided exact McNemar at α=0.05. **Two-sided exact McNemar has
no rejection region below n_d = 6**; every contrast below has n_d between 18 and
75, so all are measurements and none carries the NOT A MEASUREMENT label.

Every packed cell in the artifact carries `comparability: SOUND
(post-f67f2b2a and post-3fc4eede…)`.

## 6. The defect this run hit, and why the env var was not optional

**All five arms failed on the first launch**, identically, at worker drain:

```
worker drain failed: memphant-worker: store=postgres
job … failed (attempt 1): backend error: error returned from database:
conflicting key value violates exclusion constraint
"memphant_memory_unit_subject_valid_excl"
```

Five independent arms on five independent auto-dropped scratch DBs, all at
attempt 1 — deterministic, not contention. Isolated with a paired
`--limit-attempts 40` smoke differing in **one variable**:

| `MEMPHANT_FACT_EXTRACTION` | result |
|---|---|
| `1` (trunk's new default) | rc=1, the exclusion-constraint conflict |
| `0` | rc=0, clean drain (`done_jobs=21630`, pending 0, dead 0) |

Cause: `40ba26cf` flipped fact extraction default-ON, so the reflect path mints
explicit `{scope}:{family}:{phrase}` keys in place of collision-free
content-hash auto keys, and two semantic units sharing
`(tenant, subject, scope, agent_node, fact_key, kind)` with overlapping validity
violate the GiST constraint at
`memphant_migrations/versions/20260703_001_wsa_bootstrap.sql:833`.

The fix is **owned by another session** and nothing in `crates/memphant-core`
was touched here. A code-path reading was handed over and is recorded there as
**inference, not measurement** — no rows were captured, because the scratch DBs
auto-drop and re-running against a non-scratch DB would have reintroduced the
shared-DB job-debris problem this program already closed.

**Standing note for any harness run on `accuracy-first` until it is fixed: set
`MEMPHANT_FACT_EXTRACTION=0` or the drain will fail.**
